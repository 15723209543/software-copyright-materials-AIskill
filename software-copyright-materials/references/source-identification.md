# 程序鉴别材料：交存选取与 Word 排版验收

## 法律底线与用户额外要求

《计算机软件著作权登记办法》规定：程序和文档鉴别材料通常由前、后各连续30页构成；不足60页则全部提交。除特定情形外程序每页不少于50行，文档每页不少于30行。官方来源：https://www.ncac.gov.cn/xxfb/flfg/bmgz/202410/t20241015_869486.html

**用户额外要求**：整个源代码材料正文宋体，源码文件开头标题黑体二号（22pt），写出相对路径与文件名；每个实际 Word 页面均≥50行真实非空源码，没有大面积空白；不加页眉页脚。部分政府办事渠道指南却要求在源代码和文档页眉写软件全称、版本及页码，例如北京市政务服务页面：https://banshi.beijing.gov.cn/pubtask/task/1/110000000000/3e283672-76be-4c8c-98e8-0bebe9bd06bf.html 。如果当地材料格式与用户偏好冲突，说明利弊、以当次官方要求为先，**不隐瞒冲突**。

## 代码选择顺序

- 从用户上传的项目 ZIP 提取自研源码，剔除 `node_modules`、`.git`、编译输出和整包第三方依赖。先对照实际模块找出业务源程序；代码量太少时不得把第三方包充当个人创作代码。
- 程序排版顺序优先按运行入口和关键业务源文件的**完整文件次序**，并记录其哈希；多个文件拼接后产生的“人工顺序”需要明示。法律所指的“连续”通常以形成的申报源程序整体页面为准；如审查人员要求自然连续编排，应调整。
- 3000非空行以上：优先取前1500行和后1500行（两个各30页，每页50行），忽略中间仅在符合普通交存要求时允许。
- 不足3000行：源程序全部列出，按每页≥50行分配，如某页需要75—99行或因标题过多而缩小字号，应实际渲染审查。总体少于50行根本不可能满足，阻止伪造并反馈。
- 不可以删除真实逻辑来伪造函数完整性，不可以用无意义的注释补足代码行数，不可以将一行不相关的代码无限重复。筛除纯空白行用于紧凑排版时须确保剩余真实源码的相对顺序不变，并记录处理方式。

## 排版验收

- A4，页边距尽量紧凑且可打印；代码正文宋体；标题黑体二号；标题需提供精确文件相对路径。
- 使用 Word 原生文本，不转成截图；保留必要缩进，防止乱码或截断；长行不得静默裁剪。
- 对每页的**实际渲染 PDF 页面**提取带源行号的代码行，统计≥50；检查渲染总页数是否等于预期；检查是否出现空页、孤立标题、异常大量留白、字体替换和跨页溢出。
- 代码页尽量避免仅有一个文件标题出现在页末而文件代码跳到下一页；各代码文件首行标记来源文件，页间续代码可不反复加标题。
- 只有在上述检查通过时才可打包对外交付；否则修复排版并再次渲染。
