# 用户消息调用模板：填报信息必须在调用指令中填写

不要在 SKILL.md、示例 JSON 或源码中写死申请人姓名、身份证、邮箱、院校/企业、开发完成日期。每个待登记软件都应独立提供自己的项目 ZIP 与申请信息。

完整可复制模板：

- Codex：外层 `调用模板_Codex.md`
- 网页版 ChatGPT：外层 `调用模板_网页版GPT.md`

## 来源与优先级

1. **申请人/著作权人/联系人、著作权归属、发表与完成日期**：只根据**本次调用消息中用户填写**或本次明确附带的授权/合同等材料。不得自行填写旧项目用户信息或个人资料。
2. **软件名称与版本**：先取消息中的拟登记值，再检查源码版本/配置/启动页面是否一致。冲突不能静默覆盖，进入待确认清单。
3. **技术信息**：从完整源码、项目配置和文档中提取并核实，无法由源码证实的运行条件标注“依据项目文档，未实际运行验证”。
4. **官网字段**：逐项把消息里的字段映射入 `project_analysis.json` 的 `official` 字典，保持原文。消息未填写的字段用 `null`，最终MD变成 `【待申请人确认】`。
5. **敏感字段**：默认不写入MD；即使调用消息提供了证件号码和电话号码，也只输出占位符，只有用户明确写“允许证件和联系方式出现在最终MD”并将 `include_sensitive_in_md` 设置为 `true` 时才输出实际值。用户指定不允许写入MD时，证件号码、个人手机等只写 `【请直接在官网填写】`。不记录到测试日志，不上传公共仓库。

## 运行时的临时数据映射示例（不是用户数据）

```json
{
  "software_name": "<用户消息的拟登记全称>",
  "version": "<用户消息版本>",
  "official": {
    "applicant_name": "<申请人或办理人>",
    "applicant_type": "<主体类型>",
    "holder_name": "<著作权人完整名称>",
    "holder_entity_type": "<著作权人主体类型>",
    "contact_name": "<联系人>",
    "contact_email": "<邮箱>",
    "development_mode": "<开发方式>",
    "completion_date": "<开发完成日>",
    "published": "<是否发表>",
    "right_acquisition": "<原始或继受>",
    "right_scope": "<全部/部分>",
    "holder_id_number": null
  }
}
```

**注意**：占位字段不能原样当成真实姓名、真实日期或已确认事实。
